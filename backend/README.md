# HayHome backend

Настоящий сервер под фронтенд из `../src` (SolidJS). Раньше «регистрация», «объявления»,
«избранное» и «чат» жили только в `localStorage` браузера — теперь это реальный REST API
поверх SQLite, общий для всех пользователей.

Язык — Go (без CGO: используется чистый Go-драйвер `modernc.org/sqlite`, поэтому сборка
работает и на Windows без установленного C-компилятора).

## Запуск

```bash
cd backend
DEV_MODE=1 go run .
```

По умолчанию слушает `:8080`, создаёт файл `bnak.db` рядом с собой и папку `uploads/`
для файлов. При первом запуске на пустой базе засеивает несколько демо-объявлений
(см. `seed.go`) — удобно, чтобы `GET /api/listings` сразу что-то возвращал.

Собрать бинарник:

```bash
go build -o bnak-backend .
./bnak-backend
```

### Переменные окружения

| Переменная    | По умолчанию   | Смысл |
|---------------|----------------|-------|
| `PORT`        | `8080`         | порт HTTP-сервера |
| `DB_PATH`     | `./bnak.db`    | путь к файлу SQLite |
| `UPLOADS_DIR` | `./uploads`    | куда сохранять загруженные фото/файлы (публично раздаётся по `/uploads/...`) |
| `PRIVATE_DOCUMENTS_DIR` | `./private-documents` | куда сохранять документы о собственности (0700, никогда не раздаётся публично — только через `/api/admin/listings/{id}/document`) |
| `CORS_ORIGIN` | `*` в dev, обязателен в проде | список разрешённых origin фронтенда через запятую (`https://hayhome.am,https://www.hayhome.am`). Пустой список или `*` при `DEV_MODE=0` — сервер не запустится |
| `PUBLIC_BASE_URL` | `http://localhost:$PORT` в dev, обязателен в проде | публичный URL, по которому доступен этот сервер; в проде обязателен `https://` |
| `OPERATOR_EMAIL` | `support@hayhome.am` в dev, обязателен в проде | контактный email оператора, показывается на страницах юридической информации фронтенда |
| `OPERATOR_CITY` | `Yerevan` в dev, обязателен в проде | город деятельности оператора, показывается на страницах юридической информации фронтенда |
| `DEV_MODE`    | `0` (выключен) | `1`/`true` включает dev-режим локальной разработки: `devCode` в ответе (см. ниже про SMS) и ослабленные проверки выше. Для локальной разработки задайте `DEV_MODE=1` явно — без переменной или с `0`/`false` сервер стартует в production-режиме. Любое другое значение — ошибка запуска |
| `NOTIFICORE_API_KEY` | не задан | ключ Notificore (`X-API-KEY`, личный кабинет → «Интеграции и API» → «SMPP/API Password», `live_...` для прод, `test_...` для теста). Пока пуст — реальные SMS не отправляются, работает старое dev-поведение (код в лог/`devCode`). См. «Реальная отправка SMS» ниже |
| `NOTIFICORE_SENDER` | `HayHome` | альфа-имя отправителя SMS (originator), до 11 символов — должно быть одобрено в личном кабинете Notificore для стран, куда шлёте |
| `SEED_DEMO_DATA` | `0` (выключено) | `1`/`true` — при старте на пустой базе добавить несколько демонстрационных объявлений (см. `seed.go`). Не зависит от `DEV_MODE`: по умолчанию выключено и в деве, и в проде — свежая база всегда даёт пустую ленту, пока явно не попросите демо-данные |
| `ADMIN_USERNAME` | пусто | логин супер-пользователя панели управления — задайте один раз при первом запуске на пустой базе (см. ниже) |
| `ADMIN_PASSWORD` | пусто | пароль супер-пользователя, вместе с `ADMIN_USERNAME` — см. ниже |
| `YANDEX_TRANSLATE_API_KEY` | не задан | API-ключ Yandex Translate (Yandex Cloud → сервисный аккаунт → API-ключ). Пока пуст — описания объявлений и сообщения чата отдаются как есть, без перевода. См. `translate.go` |
| `YANDEX_FOLDER_ID` | не задан | ID каталога Yandex Cloud, к которому привязан сервисный аккаунт из `YANDEX_TRANSLATE_API_KEY` |
| `YANDEX_SPEECHKIT_API_KEY` | не задан | API-ключ Yandex SpeechKit (сервисному аккаунту нужна роль `ai.speechkit-stt.user`), тот же `YANDEX_FOLDER_ID`. Расшифровка голосовых сообщений по кнопке в чате — пока пуст, кнопка вернёт ошибку. Требует `ffmpeg` в `PATH` на сервере (голосовые пишутся в webm/ogg, SpeechKit понимает только oggopus/lpcm/mp3). См. `speechkit.go` |
| `YANDEX_MAPS_API_KEY` | не задан | Тот же ключ, что и `VITE_YANDEX_MAPS_API_KEY` на фронтенде (продукт "JavaScript API и HTTP Геокодер" в консоли Yandex). Переводит адрес объявления (город/район/улица) в координаты метки на карте при создании/редактировании. Пока пуст или адрес не распознан — координаты остаются старым фолбэком (случайная точка у центра города). См. `geocode.go`. Разово пересчитать координаты уже опубликованных объявлений — `POST /api/admin/listings/regeocode` (сессия администратора) |

Язык интерфейса каждого пользователя запоминается в `users.lang` (обновляется из заголовка
`X-Lang`, который фронтенд шлёт на каждый запрос, см. `withUser` в `auth.go`). Это позволяет
переводить чат в реальном времени под каждого получателя: когда участник A пишет на армянском,
а у участника B язык интерфейса — русский, B получает сообщение по WebSocket уже переведённым
на русский, без ручного действия и без повторного запроса (см. `publishChatMessage` в `chat.go`).
Если языки отправителя и получателя совпадают, перевод не запрашивается.

## Что здесь по-настоящему, а что ещё нет

**Реально работает:**
- регистрация/вход по номеру телефона с кодом подтверждения и сессией (токен, 30 дней);
- объявления: создание, редактирование, удаление, список с фильтрами, чужие видят только
  подтверждённые (`status = 'active'`);
- при публикации объявления обязателен защитный код кадастрового сертификата
  (`cadastre_code`) — см. раздел «Проверка по кадастру» ниже;
- окно подтверждения «раз в 72 часа» — реально хранится (`confirmed_at`/`expires_at`) и реально
  проверяется фоновой задачей раз в минуту (`sweepExpiredListings` в `listings.go`), а не только
  «пока открыта вкладка», как было в демо;
- загрузка фото объявлений и вложений чата — реально сохраняются на диск и раздаются по HTTP;
- документ о собственности — обязателен при публикации, сохраняется в приватную (не веб-раздаваемую)
  папку, доступен владельцу только как metadata и администратору только как скачивание;
- избранное и переписка — общие для всех пользователей, не привязаны к одному браузеру;
- жалоба «уже сдана» прячет объявление до ответа владельца;
- панель администратора (`/api/admin/...`, см. `admin.go` и `admin_auth.go`): список всех
  пользователей, список всех жалоб с решением (отклонить/подтвердить), список всех объявлений
  с кадастровым кодом и принудительной сменой статуса или удалением. **Полностью отдельная от
  обычных пользователей система входа** — свой логин и пароль, свои сессии
  (`admins`/`admin_sessions`), никак не связана с `users`/`sessions` и номером телефона. На
  фронтенде это отдельная страница (`control.html`), не связанная ссылками с обычным сайтом —
  см. «Как это подключено» ниже.

### Первый вход в панель администратора

Таблица `admins` при первом запуске пуста — залогиниться некуда, пока вы явно не зададите
`ADMIN_USERNAME`/`ADMIN_PASSWORD` при старте сервера **на пустой базе admins** (проверяется
один раз в `ensureBootstrapAdmin`, дальше эти переменные окружения ни на что не влияют —
незачем держать пароль в открытом виде в окружении постоянно). Например:

```bash
ADMIN_USERNAME=owner ADMIN_PASSWORD='смените-меня' go run .
```

После первого запуска откройте `control.html` фронтенда и войдите этой парой. Сменить логин/
пароль потом можно только напрямую в базе (`UPDATE admins SET ...` с новым `password_hash`/
`password_salt`, см. `hashPassword` в `admin_auth.go`) — самостоятельной смены пароля через
UI сейчас нет, это внутренний инструмент на одного оператора.

## Реальная отправка SMS (Notificore)

`POST /api/auth/request-code` шлёт код через [Notificore](https://help.notificore.ru/#rest-full-api)
(`backend/notificore.go`, `PUT https://api.notificore.ru/v1.0/sms/create`), если задан
`NOTIFICORE_API_KEY`. Номер телефона может быть из любой страны — ограничения на страны в
коде нет, только на стороне Notificore (баланс, разрешённые направления, одобренный
`NOTIFICORE_SENDER` для нужных стран — настраивается в личном кабинете). Список стран для
выбора на фронтенде — `src/countries.js`, ~100 стран с кодом, маской и допустимой длиной
номера; при необходимости туда можно дописать ещё.

Пока `NOTIFICORE_API_KEY` пуст, поведение как раньше: код пишется в лог сервера и (только при
`DEV_MODE=1`) возвращается в ответе как `devCode`, чтобы фронтенд работал end-to-end без
единого реального SMS. В проде обязательно поставьте `DEV_MODE=0`, чтобы код не утекал в
ответ API.

**Намеренно не сделано** — для этого нужны решения, которые может завести только владелец
продукта:

1. **Приём платежей.** Баланс/кошелёк в приложении нет — вместо денежной проверки используется
   защитный код кадастрового сертификата (см. ниже).
2. Правило «3 подтверждённых жалобы снимают объявление» упрощено до одной жалобы — это
   помечено `TODO` в `listings.go`, `handleReportListing`. Администратор может подтвердить
   («uphold») или отклонить любую жалобу вручную через панель.

## Проверка по кадастру

Вместо оплаты — при публикации объявления `POST /api/listings` требует непустой `cadastreCode`
(400 без него, см. `listingInput`/`handleCreateListing` в `listings.go`): защитный код
кадастрового сертификата о собственности, который владелец получает при регистрации права
собственности в кадастре. Отдельно, тем же запросом, обязателен и сам документ о собственности
(PDF/JPEG/PNG, до 10 МБ) — он сохраняется приватно (см. `documents.go`,
`PRIVATE_DOCUMENTS_DIR`) и пока не проверяется автоматически, только вручную через
`GET /api/admin/listings/{id}/document`.

Что это даёт: код сохраняется вместе с объявлением (`listings.cadastre_code`) и показывается
на странице объявления и в панели администратора со ссылкой на сайт кадастрового комитета
Армении (`https://www.cadastre.am`) — арендатор или администратор может вручную свериться,
что код существует и относится к этому адресу.

**Это не автоматическая проверка.** У кадастрового комитета нет опубликованного API для
программной сверки кода — сверка сейчас ручная, по ссылке. Если у вас есть доступ к такому
API (например, по официальному соглашению с комитетом), замените ручную ссылку в
`src/screens/Listing.jsx` и `src/AdminApp.jsx` на настоящий вызов при публикации
(`handleCreateListing`/`handleUpdateListing` в `listings.go`) — сейчас код только сохраняется
и отображается, подлинность не проверяется сервером автоматически.

## API

Все тела запросов/ответов — JSON, кроме загрузки файлов (`multipart/form-data`).
Авторизация — заголовок `Authorization: Bearer <token>`, полученный из `/api/auth/register`,
`/api/auth/login` или `/api/auth/reset-password`.

### Аутентификация
Вход по телефону + паролю; SMS-код нужен только один раз — при регистрации и при сбросе
пароля (см. комментарий в начале `auth.go`).

| Метод и путь | Auth | Описание |
|---|---|---|
| `POST /api/auth/start` `{phone}` | — | новый номер → отправляет SMS-код (`{exists:false, sent:true}`); уже зарегистрированный → `{exists:true}`, дальше пароль |
| `POST /api/auth/request-code` `{phone}` | — | повторная отправка кода («отправить снова», «забыли пароль») |
| `POST /api/auth/verify-code` `{phone, code}` | — | подтверждает код из SMS, окно 10 минут на пароль |
| `POST /api/auth/register` `{phone, password, name, role}` | — | новый номер: пароль (не короче 8 символов) + имя/роль → аккаунт и сессия, возвращает `{token, user, isNew:true}` |
| `POST /api/auth/login` `{phone, password}` | — | существующий номер → `{token, user, isNew:false}` |
| `POST /api/auth/reset-password` `{phone, password}` | — | новый пароль по подтверждённому коду (после `verify-code`), сразу выполняет вход |
| `POST /api/auth/logout` | — | завершает текущую сессию |
| `GET /api/me` | ✅ | текущий пользователь |

| Метод и путь | Auth | Описание |

| `GET /api/listings?deal=&city=&rooms=&priceMin=&priceMax=&areaMin=&areaMax=&query=` | — | список активных объявлений с фильтрами |
| `GET /api/listings/{id}` | — | одно объявление + автор + фото |
| `GET /api/listings/mine` | ✅ | все свои объявления, любой статус |
| `POST /api/listings` (multipart, поле `listing` — JSON, поле `document` — файл) | ✅ | создать (`cadastreCode` и документ о собственности — PDF/JPEG/PNG, до 10 МБ — обязательны) |
| `PUT /api/listings/{id}` | ✅ (владелец) | изменить (документ не переотправляется) |

| `DELETE /api/listings/{id}/photos?url=...` | ✅ (владелец) | удалить фото |

### Вложения чата
| `POST /api/uploads` (multipart, поле `file`) | ✅ | загрузить файл, вернёт `{url, name, size}` |

### Избранное
| `GET /api/favorites` | ✅ | список |
| `POST /api/favorites/{listingId}` | ✅ | добавить |
| `DELETE /api/favorites/{listingId}` | ✅ | убрать |

### Чат
| `GET /api/threads` | ✅ | список диалогов с последним сообщением и счётчиком непрочитанных |
| `POST /api/threads` `{listingId}` | ✅ | открыть/найти диалог по объявлению |

### Панель администратора
`POST /api/admin/login` не требует авторизации (это и есть вход). Все остальные — заголовок
`Authorization: Bearer <admin-токен>`, полученный из `/login`; токен обычного пользователя
здесь не подойдёт ни при каких условиях (иначе `401`).

| Метод и путь | Auth | Описание |
|---|---|---|
| `POST /api/admin/login` `{username, password}` | — | вход, возвращает `{token}` |
| `POST /api/admin/logout` | ✅ | завершить сессию администратора |
| `GET /api/admin/users` | ✅ | все пользователи |
| `GET /api/admin/reports?status=` | ✅ | все жалобы + объявление (с кадастровым кодом) + жалобщик + владелец |
| `POST /api/admin/reports/{id}/resolve` `{action}` | ✅ | `action`: `dismiss` (отклонить, вернуть в выдачу) \| `uphold` (подтвердить, снять объявление) |
| `GET /api/admin/listings?status=` | ✅ | все объявления любого статуса, с кадастровым кодом |
| `POST /api/admin/listings/{id}/status` `{status}` | ✅ | принудительно сменить статус |
| `DELETE /api/admin/listings/{id}` | ✅ | удалить объявление полностью (и приватный файл документа) |
| `GET /api/admin/listings/{id}/document` | ✅ | скачать/просмотреть сам документ о собственности (`Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, без кеша) |

Статика: `GET /uploads/...` — раздача загруженных файлов.

## Как это подключено к фронтенду

`../src/store.js` знает про этот сервер для всего, что касается обычных пользователей:
реальный вход/регистрация, объявления (с защитным кодом кадастра), фото, избранное, чат —
всё идёт через этот API (`fetch`-обёртка — `../src/api.js`), токен из `/api/auth/verify`
сохраняется в `localStorage` и подставляется в заголовок `Authorization`. Демо-каталог
(`../src/data.js`) остаётся отдельной витриной и в API не ходит — оба источника объединяются
в одних и тех же списках на фронтенде (см. комментарии в `store.js` про `remote:true`).

Панель администратора в эту же сборку **не входит**: это отдельная HTML-страница
(`../control.html` → `../src/AdminApp.jsx`), которая не импортирует `store.js` и никак не
связана ссылками с обычным сайтом — обычный пользователь не видит ни кнопки, ни пункта меню,
ведущих туда, и не получает её код в основном бандле `index.html`. Токен админ-сессии хранится
в `localStorage` под отдельным ключом, не пересекающимся с обычным пользовательским. См.
раздел «Первый вход в панель администратора» выше.

## Данные / модель

SQLite, файл `bnak.db`, схема — в `db.go` (`users`, `otp_codes`, `sessions`, `listings`
с полем `cadastre_code`, `listing_photos`, `listing_documents`, `favorites`, `reports`,
`threads`, `messages`, `admins`, `admin_sessions`). Порог по нагрузке для SQLite — несколько десятков одновременных
запросов на запись в секунду; для реального продакшна с заметным трафиком имеет смысл в
какой-то момент перейти на Postgres — но менять для этого почти ничего не придётся: весь
доступ к БД идёт через стандартный `database/sql`.

## Продакшн-чеклист (когда будете разворачивать по-настоящему)

- не задавать `DEV_MODE` вообще (или явно `0`) — это production-режим по умолчанию; `CORS_ORIGIN`,
  `PUBLIC_BASE_URL`, `OPERATOR_EMAIL`, `OPERATOR_CITY` в нём обязательны, сервер откажется
  стартовать без них (или с `CORS_ORIGIN=*`);
- подключить настоящего SMS-провайдера (см. ниже) до того, как пускать реальных пользователей;
- держать сервер за HTTPS-реверс-прокси (Caddy сам получает сертификат Let's Encrypt, это
  проще всего) — сам Go-сервер отдаёт только plain HTTP;
- `bnak.db`, `uploads/` и `private-documents/` — регулярно бэкапить (это единственное постоянное хранилище);
- задать systemd-unit (или Docker-контейнер) для автозапуска и рестарта при падении;
- панель администратора: логин/пароль — единственная защита, `control.html` в проде стоит
  переименовать на что-то менее угадываемое (просто отредактируйте имя файла и путь до него
  на сервере/в nginx) и, если возможно, дополнительно закрыть по IP на уровне реверс-прокси.
